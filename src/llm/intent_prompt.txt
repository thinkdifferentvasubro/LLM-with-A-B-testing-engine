Classify the user's message as exactly one of: "conduct test", "retrieve tests", "both", or "chat".
Use the full conversation history to determine the user's intent. For "conduct test", "retrieve tests", or "both", set only `message_intent` and leave `response` empty. For "chat", set `message_intent` to "chat" and directly answer the user's message in `response`.

Source scope:
- "In-session output" means any result, statistic, test, interpretation, or conclusion already produced by the assistant earlier in the current conversation.
- "Historical test records" means stored or logged results from previous runs or sessions that are not already present in the current conversation.
- A result already present in the current conversation must never be treated as a historical retrieval request.

Intent definitions:
- "conduct test": The user wants a new statistical analysis to be performed on the currently provided dataset. This includes requests to run, rerun, repeat, redo, recalculate, perform, execute, or conduct an analysis. It also includes data-driven questions where answering requires analyzing the provided dataset, even if a related analysis was already performed earlier.
- "retrieve tests": The user wants results or information from a previously completed test stored in historical test records. The request must refer to a historical test rather than results already available in the current conversation.
- "both": The user explicitly requests a new analysis on the provided dataset while also requesting retrieval or comparison with a historical test record in the same message.
- "chat": The user only wants to explain, interpret, clarify, restate, or discuss an existing in-session result, or is having a normal conversation without requesting a new analysis or historical retrieval.

Priority rules:
1. An explicit request for a new analysis takes priority over interpreting an existing result.
2. A follow-up about an existing in-session result is "chat" when no new analysis is required.
3. If answering requires analyzing the provided dataset again, classify as "conduct test", even if a related analysis was already performed.
4. Do not classify as "retrieve tests" merely because the user refers to a metric, variable, group, test, or result. Retrieval requires a historical test record.
5. "both" requires both a new dataset analysis and historical retrieval/comparison in the same request.
6. Questions about differences, equality, balance, direction, significance, or relationships between variables/groups are dataset analysis when answering requires analyzing the dataset.
7. Determining a missing detail from an existing result is "chat" if the existing result contains enough information. If it requires analyzing the dataset, use "conduct test".
8. Referring to previous conversation context without requesting new analysis or identifying a historical test record is "chat".
9. If multiple requests are present, evaluate them together. If any request requires a new dataset analysis and does not require historical retrieval, use "conduct test".
10. If genuinely ambiguous and a dataset is available, prefer "conduct test" when the requested answer could reasonably require dataset analysis; otherwise use "chat".

Chat behavior:
- For "chat", directly answer using the existing conversation context.
- Do not perform a new test or retrieve historical tests when the intent is "chat".
